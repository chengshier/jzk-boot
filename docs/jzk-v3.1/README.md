# 九州康 JZK V3.1 三批次实施说明

本目录对应以下叠加式分支：

```text
feat/jzk-v3.1-phase1-closure
└─ feat/jzk-v3.1-phase2-business
   └─ feat/jzk-v3.1-phase3-operations
```

三批次 PR 均保持 Draft，代码编译和静态检查不等于真实环境 UAT。

## 第一批：P0 统一收口

已落地：

- 普通关系绑定只允许首次建立；
- 已有关系必须走换绑申请，管理员特殊情况走强制调整专用入口；
- 关系人数规则支持角色、区域、版本、优先级和启停；
- 默认 50 人、80% 预警、超额拒绝；
- 换绑申请预占目标上级名额，驳回或取消释放，审核通过消费；
- App 仅开放普通用户、创客、合伙人、区县代理四类前台身份；
- 真实健康厂商接入默认关闭，保留通用 Provider/Adapter 底座；
- 创客、合伙人、区县代理佣金能力模板完整初始化，但全部默认关闭。

## 第二批：业绩、经营与佣金闭环

已落地：

- 独立业绩账本；
- 来源成员、关系、区域和受益人快照；
- 线下销售登记、审核、真实库存扣减和退货回补；
- 线下经营收益账本，固定标记 `OFFLINE_REALIZED`；
- 区县代理调拨价差与平台应付佣金分账；
- 创客、合伙人、区县代理佣金规则草稿、试算、发布、停用和版本时间窗；
- 无已发布规则时只记录业务、业绩和匹配日志，不生成可提现佣金；
- 线上退款、线下退货和调拨退回分别冲正业绩、经营收益和佣金。

初始化佣金模板仍全部关闭，不填写生产比例，不自动追溯历史业务。

## 第三批：运营与非厂商健康闭环

### 库存盘点

- 创建账面快照；
- 逐项录入实盘数量；
- 提交和后台审核；
- 审核前校验快照之后是否发生真实库存变化；
- 盘盈通过统一入库流水；
- 盘亏通过冻结后出库；
- 禁止直接覆盖库存数量字段。

### 异常收货 V2

- 按异常商品明细配置补发、退款、退回、接受或组合方案；
- 待确认和已完成方案共同占用可处理数量；
- 处理数量不得超过短缺数量加破损数量；
- 退款数量必须配置正数退款金额；
- 纯补发方案全部真实完成后，原业务恢复待收货；
- 涉及退款、退回或接受现状时保持异常锁定，等待真实资金、退货或差额库存动作；
- 不通过只修改状态伪造库存、业绩或佣金闭环。

### 统一私有文件

- `jk_file_object` 统一记录文件元数据；
- 支持 `LOCAL_PRIVATE` 和 MinIO；
- 默认总开关关闭；
- 仅允许图片和 PDF；
- 上传文件与服务端生成文件使用同一存储入口；
- 私有文件必须经过登录接口和所有权校验下载；
- 配置缺失或写入失败时明确报错，不返回伪成功 URL。

### 真实微信小程序码

- 调用微信 `getwxacodeunlimit`；
- 校验微信返回真实 PNG；
- 写入统一私有文件存储；
- 按场景、角色和用户缓存；
- 微信凭据、私有存储或场景未就绪时明确不可用；
- 默认场景 `AGENT_BIND` 关闭，不生成占位二维码。

### 微信订阅消息任务

- 总开关 `jk.wechat.subscribe-enabled` 默认 `false`；
- 支持审核结果、调拨状态、收货提醒和提现状态模板；
- 状态包括待发送、等待重试、等待配置、等待接收人授权、发送成功和发送失败；
- 缺少配置或可信 openId 时不进行无意义周期重试；
- 只有微信接口明确返回 `errcode=0` 才标记发送成功；
- 管理端可查看、手动处理和重新入队，但不能绕过微信授权。

### 健康周报和月报

- 周报最多 7 天，月报最多 31 天；
- 只汇总真实血糖、饮食、运动和用药记录；
- 不补齐缺失数据；
- 不生成医疗诊断、处方或虚构设备记录；
- 报告明确标注仅用于健康记录整理。

## SQL 执行顺序

执行前必须备份相关业务表、菜单表和权限表。

```text
第一批
1. sql/jiuzhoukang/fix/jk_v31_phase1_relation_quota_upgrade.sql
2. sql/jiuzhoukang/fix/jk_v31_commission_templates_disabled.sql

第二批
3. sql/jiuzhoukang/fix/jk_v31_phase2_business_closure.sql
4. sql/jiuzhoukang/fix/jk_v31_phase2_menu_permission_upgrade.sql

第三批
5. sql/jiuzhoukang/fix/jk_v31_phase3_operations_upgrade.sql
6. sql/jiuzhoukang/fix/jk_v31_phase3_receive_exception_v2_item_patch.sql
7. sql/jiuzhoukang/fix/jk_v31_phase3_subscription_task_patch.sql
8. sql/jiuzhoukang/fix/jk_v31_phase3_menu_permission_patch.sql
```

执行后需核对：

- 表结构和唯一索引；
- `eb_system_menu` 菜单、按钮及 authority；
- 普通后台角色只获得业务所需权限；
- 盘点审核、异常方案处理、微信任务执行等高风险按钮不自动广泛授权；
- `AGENT_BIND` 场景保持关闭；
- 微信订阅总开关保持关闭；
- 创客、合伙人、区县代理佣金模板保持关闭。

## 默认配置

```yaml
jk:
  health:
    provider-enabled: false
    callback-enabled: false
  storage:
    enabled: false
    provider: LOCAL_PRIVATE
  wechat:
    enabled: false
    subscribe-enabled: false
```

在没有真实厂商协议时继续禁止启用健康 Provider。第三批健康报告、手工记录、趋势、档案、提醒和授权不依赖厂商接入。

## 真实环境准入

合并前仍需使用真实 MySQL 5.7、真实 Token、普通管理员、微信开发者工具和真机执行：

1. 第一批关系、额度、权限、库存、提现和普通零售 P0 回归；
2. 第二批线上零售、线下销售、平台订货、调拨、退款、退货、结算和冲正；
3. 盘点快照后并发库存变化校验；
4. 盘盈、盘亏库存流水和批次成本校验；
5. 异常收货 V2 数量占用、幂等、补发、退款和退回边界；
6. 本地私有文件和 MinIO 上传、读取、越权下载、过期访问；
7. 真实微信小程序码生成、缓存和关系绑定；
8. 订阅消息关闭、缺配置、缺授权、成功、失败和重试；
9. 健康周报月报真实数据聚合和隐私权限；
10. Admin 菜单、按钮 authority、数据范围和 App 所有入口。

未完成上述环境验证前，三个批次 PR 均不得标记为正式验收通过。
