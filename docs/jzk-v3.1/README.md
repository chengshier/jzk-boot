# 九州康 JZK V3.1 第一批统一收口

本目录记录 `feat/jzk-v3.1-phase1-closure` 分支的实施范围、数据库变更、配置边界、验收步骤与后续批次边界。

## 当前 PR 范围

本分支按 V3.1 先执行第一批 P0 收口，不代表第二、第三批已经完成。

已落地：

- 普通关系绑定只允许首次建立；
- 已有关系必须走换绑申请，管理员特殊情况走强制调整专用入口；
- 关系人数规则支持角色、区域、版本、优先级和启停；
- 默认 50 人、80% 预警、超额拒绝；
- 换绑申请预占目标上级名额，驳回/取消释放，审核通过消费；
- App 仅开放普通用户、创客、合伙人、区县代理四类前台身份；
- 真实健康厂商接入默认关闭，保留通用 Provider/Adapter 底座；
- 创客、合伙人、区县代理佣金能力模板已初始化，但全部默认关闭。

## 健康厂商配置

默认配置：

```yaml
jk:
  health:
    provider-enabled: false
    callback-enabled: false
```

在厂商接口文档、测试账号、测试设备、回调协议、字段、错误码和签名规则不完整时，不得开启 `provider-enabled`。

总开关关闭时：

- 不执行到期拉取；
- 不产生周期性拉取失败日志；
- 不允许启用 Provider；
- 主动拉取和厂商回调统一返回 `provider disabled`；
- 手工健康记录、趋势、提醒、档案和授权不受影响。

## 第一批真实环境准入

CI 编译和静态检查不等于 UAT。合并前仍需使用真实数据库、真实 Token、普通管理员和小程序终端验证：

1. 首次绑定成功；
2. 已有关系不能被普通接口覆盖；
3. 换绑申请预占、驳回释放、审核通过消费；
4. 第 50/51 人并发绑定不会超限；
5. 管理员强制调整必须填写原因并产生审核日志；
6. `spreadUid` 与 `jk_agent_relation` 一致；
7. 扩展角色不显示当前业务菜单；
8. 无厂商时 App 不出现可完成的设备绑定流程；
9. 普通管理员 authority 和数据范围正确；
10. 库存、提现、普通零售及退款 P0 回归无新增问题。
