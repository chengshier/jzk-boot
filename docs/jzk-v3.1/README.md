# 九州康 JZK V3.1 三批次统一收口

分支：`feat/jzk-v3.1-phase1-closure`

关联 PR：

- `jzk-boot#2`
- `jzk-vue#2`
- `jzk-app#2`

三个仓库使用同一分支名和 PR 标题。由于 GitHub 不支持一个 PR 跨越多个仓库，因此采用关联 Draft PR，而不是将三端误称为单一仓库 PR。

## 一、当前批次状态

### 第一批

已进入代码：

- 首次绑定、审核换绑、管理员强制调整分离；
- 可配置直属人数上限和换绑预占；
- 第 50/51 人并发防穿透；
- 创客、合伙人、区县代理佣金模板默认关闭；
- 健康设备厂商总开关默认关闭；
- 小程序角色范围和设备入口降级；
- 管理端关系抽屉和人数规则页面。

第一批 JDK 8、管理端构建和小程序静态检查曾通过，但真实数据库、真实 Token、普通管理员和真机 UAT 尚未完成。

### 第二批

已进入代码：

1. **独立业绩账本** `jk_performance_record`
   - 线上零售、线下终端销售、平台订货、库存调拨；
   - 业务发生时关系快照；
   - 幂等请求号；
   - 退款和退回按比例冲减，不删除历史记录。

2. **独立经营收益账本** `jk_operation_profit_record`
   - 收益性质固定区分 `OFFLINE_REALIZED`；
   - 区县代理调拨价差和本人线下销售毛利不进入平台提现账户；
   - 批次成本快照缺失时不生成经营毛利。

3. **线下终端销售**
   - 创客、合伙人和区县代理从本人真实库存选择商品；
   - 确认成交时真实冻结并出库；
   - 读取 FIFO 批次成本；
   - 大额、重复客户、缺少凭证等进入审核；
   - 审核通过前不扣库存、不记业绩、不记佣金；
   - 退货回补库存，并冲减业绩、经营收益和平台佣金。

4. **角色佣金 V3.1**
   - 草稿、试算、发布、停用；
   - 编辑已发布规则时创建新版本；
   - 支持受益人快照、计算基数、计算方式、叠加组、上限和风险条件；
   - 所有初始化模板继续默认关闭；
   - 只有 `PUBLISHED + status=true + 已到生效时间` 的规则参与计算；
   - 旧佣金计算器跳过 V3.1 规则，防止重复入账。

5. **事件接入**
   - 普通零售使用下单时归属快照，不读取完成时最新关系；
   - 平台订货收货生成订货业绩和可选平台补贴；
   - 调拨收货固化批次成本、调拨业绩和线下经营价差；
   - 零售退款、调拨退回执行佣金、业绩和经营收益冲正。

### 第三批

已进入代码：

1. **库存盘点**
   - 创建账面快照；
   - 提交全部实盘数量后逻辑冻结库存账户；
   - 库存唯一写入口阻断订货、调拨、销售和退货等非盘点动作；
   - 审核通过只通过 `StockFlowService` 生成盘盈/盘亏流水；
   - 审核前再次核对库存数量和版本，防止冻结期间数据漂移。

2. **异常收货 V2**
   - 后台提出处理方案；
   - 部分收货、退款、赔付等方案先写快照；
   - 收货方和发货方确认后才执行；
   - 正常实收部分入库；
   - 按实际实收金额生成业绩、经营收益和可选平台佣金；
   - 退款与赔付金额记录为线下履约待办，不擅自修改平台资金账户；
   - 旧的直接“处理完成”入口被收口到 V2 方案流程。

3. **MinIO 对象存储与导出任务**
   - `jk.storage.minio.enabled=false` 默认关闭；
   - 报表文件只保存对象键和元数据，不保存数据库正文或服务器临时绝对路径；
   - 支持业绩、经营收益、线下销售和库存盘点 CSV；
   - 生成短期签名下载地址；
   - 失败任务可重试，下载次数有记录。

4. **微信推广场景码**
   - `jk.wechat.miniprogram-code.enabled=false` 默认关闭；
   - 使用随机 opaque scene，不把用户 ID 放进二维码；
   - 启用后调用微信真实 `getwxacodeunlimit`；
   - 图片保存到 MinIO；
   - 记录扫码、新增用户、首次绑定、有效绑定、购买人数和成交金额。

5. **订阅消息队列**
   - `jk.wechat.subscription.enabled=false` 默认关闭；
   - 事件键和接收人幂等；
   - 默认关闭时记录 `SKIPPED_DISABLED`，不伪装发送成功；
   - 启用后调用微信真实订阅消息接口；
   - 重试、退避、失败日志和人工重试入口。

6. **健康周报/月报**
   - 不依赖设备厂商；
   - 使用本人手工、管理员录入或真实设备同步数据；
   - 统计记录次数、平均、最高、最低、时段和来源；
   - 展示已有风险提醒；
   - 明确不构成医疗诊断。

## 二、数据库执行顺序

测试库执行前必须备份。

建议顺序：

1. 第一批：`jk_v31_phase1_relation_quota_upgrade.sql`
2. 第二批建表：`jk_v31_phase2_business_closure.sql`
3. 第三批建表：`jk_v31_phase3_operations_health.sql`
4. 默认关闭模板：`jk_v31_commission_templates_disabled.sql`
5. 统一兼容、权限、菜单和模板修正：`jk_v31_phase2_phase3_idempotent_upgrade.sql`

最后一个脚本是正式环境的可重复执行收口脚本，用于兼容已经存在的旧字段和旧版 `jk_report_export_task`。

## 三、外部能力配置

所有外部能力默认关闭：

```yaml
jk:
  storage:
    minio:
      enabled: false
      endpoint: ""
      access-key: ""
      secret-key: ""
      bucket: jzk-business
  wechat:
    miniprogram-code:
      enabled: false
      app-id: ""
      secret: ""
      page: pages/index/index
    subscription:
      enabled: false
      app-id: ""
      secret: ""
  health:
    provider-enabled: false
    callback-enabled: false
  offline-sale:
    audit-amount-threshold: 1000
    voucher-amount-threshold: 500
```

禁止在未配置真实参数时将开关打开。
