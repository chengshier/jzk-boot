# 九州康业务数据流与库存职责说明

## 1. 文档目的

本文件用于统一 CRMEB 原商城与九州康业务中心之间的商品、价格、库存、订货、调拨、身份、团队和收益口径，避免同一业务数据被重复录入或由多个页面分别维护。

## 2. 商品主数据

### 2.1 唯一来源

商品与 SKU 只允许在 CRMEB 原商品模块维护：

- `eb_store_product`：商品主表；
- `eb_store_product_attr_value`：SKU、规格、条码、价格、成本和原商城库存。

九州康业务表只保存 `product_id`、`sku_id` 和必要的单据快照，不再创建第二套商品档案。

### 2.2 快照与实时名称

- 价格规则、库存账户和库存流水页面应实时关联 CRMEB 商品主数据展示名称；
- 订货、调拨等已生成单据保留商品名、SKU、价格快照，商品后续改名或下架不得改变历史单据；
- 商品已删除时，历史单据仍显示快照，配置类数据则显示“商品已删除”并禁止继续启用。

## 3. 库存职责

### 3.1 平台物理库存

CRMEB 原 SKU 库存是平台物理库存的唯一主来源。普通零售和区县代向平台订货必须共享同一平台可售库存，不允许运营人员在 CRMEB 和九州康分别录入平台库存。

九州康 `PLATFORM` 库存账户只作为业务冻结、释放和出库流水镜像，不成为第二个可手工维护的库存真值。

### 3.2 分级库存

`jk_stock_account`、`jk_stock_item`、`jk_stock_flow` 和 `jk_stock_batch` 用于记录已经从平台仓转移到业务主体名下的库存：

- 区县代库存；
- 合伙人库存；
- 创客库存；
- 对应冻结、释放、出库、入库、退回和批次流水。

### 3.3 正常流转

1. 普通用户购买：走 CRMEB 原零售订单库存链路；
2. 区县代订货：审核通过时占用平台 SKU 库存，关闭时释放，发货时完成平台出库；
3. 区县代收货：自动增加区县代 `jk_stock_item` 并生成流水和批次；
4. 创客/合伙人调拨：冻结区县代库存，拨货出库，收货后增加下级库存；
5. 调拨退回：按退回单完成下级出库和上级入库。

任何页面不得要求用户对同一批货物再次手工入库。

## 4. 库存批次

- `jk_stock_item` 保存库存总量；
- `jk_stock_batch` 保存总量的批次组成、生产日期、有效期和单位成本；
- 批次由真实入库动作自动生成；
- “期初批次初始化”仅用于历史库存升级迁移，只允许超级管理员在上线前执行一次，不属于日常库存操作；
- 日常批次页面只能查询批次、库龄和维护缺失的生产日期、有效期、单位成本，不能直接修改库存数量。

## 5. 价格规则

价格规则必须关联有效 CRMEB 商品和 SKU：

- `product_id` 必须存在且未删除；
- `sku_id` 可为空，表示商品级规则；
- `sku_id` 不为空时必须属于所选商品且未删除；
- 固定价必须大于等于 0；
- 折扣率必须大于 0 且不大于 1；
- 下架商品的历史规则允许查看，但新规则启用前应提示商品状态；
- 商品或 SKU 删除后，关联配置应标记异常并禁止继续启用。

## 6. 身份与团队

CRMEB 用户表仍是用户唯一来源，九州康只附加业务身份和关系：

- 身份申请审核；
- 生效身份、冻结、解冻、取消；
- 区域代理配置；
- 上下级关系和换绑历史；
- 数据范围和业务权限。

团队详情只允许查看当前用户的直属下级。当前佣金记录没有保存“来源成员”快照，因此不能准确反推成员给上级带来的贡献，接口必须显式返回 `contributionAvailable=false`，禁止用成员本人佣金或模拟数字代替。

“业务角色、权限点、数据范围、后台用户映射、权限缓存版本”属于系统配置，不应与日常身份审核菜单平铺展示。

## 7. 当前真实接口

### App 业务中心

- `GET /api/front/jk/business/summary`

统一返回库存价值、累计收益、可提现余额和待办数量，避免 App 拉取多个列表后自行统计。

### 本人库存

- `GET /api/front/jk/stock/my`
- `GET /api/front/jk/stock/sku/{skuId}/detail`
- `GET /api/front/jk/stock/flow/list`

SKU 详情包含真实商品信息、批次、最近流水和根据入库、出库流水反推的七日期末库存趋势。冻结与释放不改变库存总量。

### 团队

- `GET /api/front/jk/team/summary`
- `GET /api/front/jk/team/member/{memberUserId}`
- `GET /api/front/jk/team/qrcode`

### 推广素材

- `GET /api/front/jk/promotion/material/list`
- `GET /api/admin/jk/promotion/material/list`
- `POST /api/admin/jk/promotion/material/save`

## 8. 后台菜单分组

按业务使用场景分组：

1. 身份与团队：身份申请审核、业务身份管理、区域代理配置、上下级关系、换绑审核；
2. 商品与价格：复用 CRMEB 商品管理、九州康价格规则；
3. 订货与调拨：平台订货、库存调拨、调拨退回；
4. 库存管理：库存主体、库存明细、库存流水、批次与库龄；
5. 收益与资金：分佣规则、佣金明细、结算、资金账户、提现审核、对账；
6. 系统配置：业务角色与权限、后台账号映射、字典、事件补偿、风险规则和数据初始化。

## 9. 后台页面使用边界

- **库存主体**：查看平台、区县代、合伙人和创客的库存归属，不录入数量；
- **库存明细**：按主体、商品和 SKU 查询，不直接编辑数量；
- **库存流水**：审计和追溯来源单据，不修改库存；
- **批次与库龄**：维护生产日期、有效期和单位成本，不修改库存数量；
- **业务身份管理**：冻结、解冻、取消身份时必须填写真实原因；
- **换绑审核**：审核通过时后端实时检查未完成调拨、库存余额、待结算佣金和处理中提现。

## 10. 页面数据规则

- 页面不得生成看起来像真实业务数据的模拟库存、批次、收益、团队动态或推广记录；
- 接口缺失时显示空状态和明确说明；
- 业务中心统计由后端汇总接口统一返回，不再由 App 拉取前 100 条列表自行统计；
- 金额统一使用 `BigDecimal` 字符串返回；
- 选择用户、商品、SKU、区域、身份和库存主体时使用远程选择器，不允许业务人员手填数据库 ID。

## 11. 上线前必须验证

1. 普通商城下单、取消、退款后的 CRMEB 库存变化；
2. 平台订货审核、库存不足、关闭释放、发货、收货；
3. 调拨审核、关闭释放、拨货、收货和退回；
4. 历史平台冻结和批次预留兼容；
5. 价格规则商品/SKU 合法性和历史异常规则；
6. 身份冻结、团队详情、换绑阻断；
7. 提现申请、驳回释放和确认打款；
8. App、Admin 与后端字段联调。

在真实数据库审计和业务回归完成前，三个 PR 必须保持 Draft，不直接合并到 `master`。
