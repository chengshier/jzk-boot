## 三、核心业务链路

### 1. 普通用户区域与下单归属

```text
下单时有效直属关系快照
→ 个人资料标准区域
→ 本单标准收货区域兜底
→ 平台默认
→ 逐订单明细写入 jk_retail_order_attribution
→ 完成、退款、佣金、业绩和推广效果只读取该快照
```

普通用户可以没有业务身份、直属上级或个人资料区域，仍可正常浏览、下单、支付和售后。收货地址不会静默覆盖个人资料区域。

### 2. 商业方案与奖励规则

```text
商业方案草稿版本
→ 选择业务奖励模板
→ 配置真实奖励值和范围
→ 按真实业务单据加载快照试算
→ 审核发布
→ 仅从生效时间开始匹配新业务
→ 生成 PLATFORM_PAYABLE
```

已确认：

- 新模板和新规则默认关闭；
- 比例、固定金额和阶梯奖励必须大于 `0` 才能发布；
- 单条规则中比例、固定金额和按数量金额互斥；
- 单笔封顶、周期封顶和总预算留空表示不限制，填写后必须大于 `0`；
- 空规则显示“未配置 / 未发布”，不显示 `¥0.00`；
- 生效开始时间必填，结束时间可空；
- 已发布版本不可直接修改，不追溯历史业务；
- `OFFLINE_REALIZED` 只进入经营收益账本，不进入佣金提现账户。

### 3. 周期业绩和阶梯奖励

```text
有效线上零售 + 经核验线下终端销售
→ 构建周期业绩草稿
→ 退款冲减
→ 奖励试算
→ 审核关闭
→ 数据库占用周期封顶和规则总预算
→ 生成真实佣金
→ 周期锁定
```

平台订货和内部库存调拨默认不等于终端销售；线下调拨价差仍属于 `OFFLINE_REALIZED`。

### 4. 退款后的佣金与推广效果

```text
真实退款完成
→ RetailOrderAttributionService.allocateRefund
→ 按订单明细实付快照分摊退款
→ 业绩冲正
→ 原佣金按剩余计奖基数比例冲正
→ 后端生成 RETAIL_REFUND 推广反向事件
```

- 原佣金、结算和提现记录不覆盖；
- 部分退款按比例冲正，累计全额退款时全部冲正；
- 已提现部分形成后续待抵扣；
- 推广打开和访客记录不删除；
- 部分退款只减推广成交金额，累计全额退款后订单不再计为有效成交；
- 净成交金额 = `RETAIL_COMPLETED` − `RETAIL_REFUND`；
- 同时输出打开转化率和访客转化率，分母为零时返回空值并显示 `--`；
- 客户端只允许上报 `OPEN`，不得提交成交或退款事件。
