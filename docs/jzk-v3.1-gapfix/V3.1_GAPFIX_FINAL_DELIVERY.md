## 三、核心业务链路

### 1. 普通用户区域与下单归属

```text
个人资料所在地区（eb_user.jk_region_code）
+ 本单收货地址标准区域（eb_user_address.jk_region_code）
+ 下单时有效直属关系
→ 创建订单时固化地址和关系
→ 每个订单明细写 jk_retail_order_attribution
→ 订单完成后佣金、业绩和推广效果只读取该快照
```

优先级：

```text
有效直属关系快照
→ 个人资料标准区域
→ 本单标准收货区域兜底
→ 平台默认
```

普通用户：

- 可以没有 `jk_user_business_role`；
- 可以没有直属上级；
- 可以暂时没有个人资料区域；
- 仍然可以正常浏览、下单、支付和售后；
- 收货地址不会静默覆盖个人资料区域。

### 2. 商业方案与收益奖励

```text
创建商业方案草稿版本
→ 从业务模板配置奖励草稿
→ 按真实业务单据加载快照试算
→ 审核发布商业方案和奖励规则
→ 仅从生效时间开始匹配新业务
→ 生成 PLATFORM_PAYABLE
```

约束：

- 所有新模板默认关闭；
- 发布版本不可直接修改；
- 历史业务不跟随新版本重算；
- 普通运营不直接配置底层技术枚举；
- 空规则显示“未配置 / 未发布”；
- `OFFLINE_REALIZED` 只进入经营收益账本，不进入佣金提现账户。

### 3. 周期业绩和阶梯奖励

```text
有效线上零售 + 经核验线下终端销售
→ 构建周期业绩草稿
→ 成员贡献与退款冲减
→ 奖励试算（不入账）
→ 审核关闭
→ 数据库占用周期封顶和规则总预算
→ 按已发布规则生成真实佣金
→ 周期锁定
```

内部库存流转默认不等于终端销售：

- 平台订货不直接计入团队销售奖励；
- 库存调拨不直接计入团队销售奖励；
- 线下调拨价差仍属于 `OFFLINE_REALIZED`。

### 4. 推广效果

```text
小程序扫码/场景打开 → 客户端仅记录 OPEN
真实零售订单完成 → 后端读取归属快照记录 RETAIL_COMPLETED
→ 管理端按场景、推广人、打开、成交和金额统计
```

客户端不能提交成交金额、推广人或成交事件。

### 环境

- MySQL 5.7、Redis、MinIO；
- 真实后台超管和普通管理员 Token；
- 真实普通用户、创客、合伙人、区县代理 Token；

### 必测主链

1. 普通用户无身份、无上级、无区域仍可下单；
2. 关系、个人资料区域、收货区域和平台默认四种归属；
3. 下单后换绑或改区域不改变历史订单；
4. 多商品、优惠券、积分、满减、运费和部分退款分摊；
5. 锁定归属只允许冲正和补偿；
6. 商业方案复制版本、发布、停用和时间窗口；
7. 新模板默认关闭；
8. 真实订单、线下销售、订货、调拨和业绩试算；
9. 周期业绩只统计有效终端销售；
10. 周期封顶和总预算最后额度并发；
11. `OFFLINE_REALIZED` 与 `PLATFORM_PAYABLE` 对账；
12. 推广打开、真实成交、退款口径和转化率；
13. 异常收货退款/退回/差额库存真实动作；
14. MinIO 报表导出和私有访问；
15. 订阅消息授权、发送、日志和失败重试；
16. 健康授权、撤销、访问日志和隐私越权测试。
